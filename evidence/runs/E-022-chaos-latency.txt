identical signature: 478 async timeouts; thread dump under load showed 8 'task-N' workers = Spring Boot's

-- ROOT CAUSE --
Spring MVC async dispatch runs the saga on applicationTaskExecutor (default core=8, UNBOUNDED queue).
Under the injection each saga occupies a worker ~3.2s (4 proxied ERP calls x 800ms; solo probe measured
3.22s vs 15.6ms clean). Capacity ~= 8 workers / 3.2s ~= 2.5-6/s < 10 RPS arrival -> unbounded queue ->
requests die at the 30s async-request timeout. The breaker NEVER opens and the retry ladder NEVER fires
(ERP calls succeed) — a dependency-latency degradation is INVISIBLE to every resilience mechanism and
surfaces only as queue-then-timeout at the facade.

-- FIX (application.yml, committed with this evidence) --
spring.task.execution.pool: core 32 / max 64 / queue 200 (bounded). Saturation now degrades to bounded
waiting instead of a silent 30s queue-then-timeout. ESB unit tests 33/33 green post-change.
